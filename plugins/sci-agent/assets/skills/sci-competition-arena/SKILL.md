# 适用场景

面向"给定若干科研任务题，交付可被评测的 Agent Skill 包，按 rubric 评分并排名"的竞赛（示例：玻尔产品赛 P4，77 题 / 10 赛道 / 每题 10 次有效评分额度 / 7 天窗口）。

## 1. 赛制先读清

- 评测口径：装进官方 Harness，在隐藏案例上运行，按 rubric 打分（示例：实际效果 40 / 使用增益 25 / 创新 15 / 可靠 10 / 生态 10）
- 额度：示例为"每题 10 次有效评分，格式不匹配或评测异常未出分不扣次数"——**失败不扣额**要写进出投策略
- 排名：按赛道汇总（示例 10 赛道 key-best 求和），同分并列；先算清"第 5 / 第 10 名差多少"再定策略
- 时间：截止前投递全部有效（示例规则：截止后统一出分），但**不要假设**，赛前确认

## 2. 赛前准备（最高优先级）

1. 抓题面 + 元数据：`/api/challenges/{id}` 与 task.md；建立 77 题清单 + 赛道映射
2. 建立基线：每题提交一个"最小可用包"，拿到第一轮真实分（这比盲猜 rubric 有用 10 倍）
3. 建评分台账：题号 / 已投次数 / 最新状态 / 最好分 / 包版本 / 时间；每天追加
4. 准备可复用包骨架：单根、SKILL.md（流程/契约/证据/SELFTEST/降级/增益）、preflight 检查器

## 3. 节奏

- 前 40% 时间：广度（每题先有分）
- 中 30%：集中提升低分题（rubric 加权高且差距大的赛道优先）
- 后 30%：只做"评分可验证的提升"，避免大重构
- 最后 2 小时：停止新设计，只投已达标的验证包；预留 30 分钟处理 429/上传失败

## 4. 常见失败

- 早期把额度撒在未评测包上 → 后期无额度
- 只优化 rubric 文案、不跑通真实案例 → 实际效果分低
- 忽略平台写回/队列停滞 → 大量 pending 未兑现
- 不看赛制就假设"截止后出分"或"重投不扣额"
