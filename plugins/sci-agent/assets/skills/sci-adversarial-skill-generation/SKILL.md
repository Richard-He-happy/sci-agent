# 适用场景

数十道题、每题都要一个可评测 Skill、单包手写来不及。用流水线把"生成—评审—改进—门控—提交"标准化。

## 1. 生成器池（异构优先）

- 强思考模型轮转：如 gpt-6.2-astra（Codex）、deepseek-v4.1-flash-1017、glm-5.4、qwen4-max、kimi-k3.1-pro
- 每轮换模型/温度；同一题产出 3-6 候选
- 提示词必须包含：题目 brief、现有最佳 SKILL、上一轮评委弱点、交付契约、规模红线（≤12KB、≤2 脚本、不得引用不存在文件）

## 2. 评委（不能与生成器同模型）

- 2-3 个独立模型按 rubric 打分（0-100）+ 给 top3 弱点
- 每 2 轮加一次"终审"（换一个更强模型，或人工规则）
- 校准：用已知官方分回测评委预测（同题历史包），记录偏差（示例 ±5-10）

## 3. 门槛（防乱投）

- 预测 ≥ 官方分 + 4~5 才进入提交候选
- preflight 必须 PASS（单根、frontmatter 完整、无缺失引用、无 GITHUB_URL/pycache）
- 记录：题号 / 包版本 / 预测分 / 评测模型 / attempt id

## 4. 多轮进化

1. 生成 → 2. 评分 → 3. 弱点回喂 → 4. 再生成（4-6 轮）→ 5. 达门槛即停
2. 保留"每轮最佳"与"最终最佳"两套快照，便于回滚
3. 收敛条件：达门槛 / 连续两轮无提升 / 时间预算用尽

## 5. 常见失败

- 生成包引用不存在脚本 → 评测失败，浪费额度
- 评委与生成器同模型 → 同质化，虚高
- 无限轮次不设收敛 → 时间和额度双输
- 未记录预测分 → 无法校准、无法复盘
