# 适用场景

两个执行体（如两个账号/两个 Agent）共享任务池与时间窗口，需要避免重复投递、互相借用额度、并保持可审计沟通。

## 1. 分工矩阵

- 按赛道/题目切分归属，写清"谁生成、谁评审、谁投递、谁兜底"
- 一方强项（如 PPT/搜索）优先给该方；另一方做交叉验证
- 每周/每天 30 分钟简报：分数、名次、pending、卡点

## 2. 差异化交付包（避免同质/去重）

- 用方把包交给对方时做"形式差异化"：rename、JSON 重排、附 ADAPTATION.md（行为不变）
- 保留原始 sha 记录，便于区分"同包重投"与"改造版"

## 3. 通信协议（文件式）

- `exchange/INBOX_<peer>.md`：只放"索引行"（消息号/时间/摘要/详情路径）
- `exchange/msg/MSG-XXXX.md`：详情；发送方追加索引行，接收方读索引再按需读详情
- 定期核对：消息号连续、时间戳校时（不同机器时钟漂移会造成"未来消息"）
- 避免把 INBOX 写成无限追加的巨型文件：控制行数/定期归档（曾因 92M 行导致读取超时）

## 4. 评审门控（shared cleared list）

- 候选包统一由"评审方"出 cleared 清单（题号/包/预测分/门槛）
- 未进 cleared 的包双方都不投
- 每批更新清单版本号 + 时间戳

## 5. 终分互报

- 截止后各自刷新最终分/名次，约定时间互换（示例 21:20）
- 交换字段：总分、赛道名次、finals、pending/failed、今日投递数、429 次数
- 合并为对照表写入终报，注明来源
